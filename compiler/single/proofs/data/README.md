# Static data and text agreement

A static image consists of a byte count and a sequence of string fragments. A placed image has those fragments at consecutive machine addresses. An object map records the address, zone, kind and reference rank of each discovered object. The foundation predicates interpret the placed words and fields through such a map.

A reader witness gives the ends of token spans and the positions of punctuation. Quoted lists also have a witness for their interpretation as data, with ordinary term parsing disabled. The source-line relation uses ACL2 values in records of the forms `(:define rulers definitions)`, `(:attach source target)`, `(:package name imports visible)`, `(:entry name)` and `(:target :linux)`. Both line lists are in reverse file order. Definitions and imports within a line remain in their written order.

`data-elaborate-program-with-quotes` computes reader events, source lines and quoted values from program text and package witnesses. The checked relations follow when elaboration succeeds. The allocation trace records objects in increasing address order from byte 32, beginning with the two fixed symbol objects. The trace is computed from the builder's passes. Its shape and reference checks operate on the allocated fields and root words.

The static scan starts at NIL, T, the two table roots and the constant index. A ranked witness gives the exact record for each reference it admits. Its records occupy distinct intervals in the placed image, and each reference field points to a record of lower rank. The interpretation of fields as ACL2 values and of the tables as package and name bindings uses the resulting map.

`data-elaborated-text-and-allocated-views-give-static-agreement` computes the reader witnesses, source lines, quotes and object map. For checked allocations in a placed image and a matching `COMMON-LISP` package witness, the theorem needs the table and object view conditions and the views of the quoted allocations. It supplies the immediate quote views and the fixed NIL and T views, and establishes the initial static predicate, constant-map agreement and arity agreement after discovery.

## Open obligations

- Prove that source admission implies successful elaboration of every canonical program and that admitted attachment graphs pass the indexed acyclicity check.
- Derive the shape, field and root checks for every admitted builder allocation trace. Establish valid views, symbol uniqueness and the agreement of all rows and bucket chains with the ACL2 world's imports and home bindings on the computed map.
- Derive the home-key condition for every quoted symbol from source package admission. Establish `proof-constant-map-p` on the placed image for all quoted allocated objects from their spellings and allocations.
- Derive the remaining representation bounds and a general acceptance theorem for well-formed input. A proof of executable error paths must account for the stop that corresponds to `compiler-error`.
- Extend the static-block theorems to programs with a `heap-limit` line. For such a program `data-build` writes the limit as an odd word after the bucket vector, and `data-image-parts` and `data-build-image-and-index` include it. `data-program-storage-input-p` excludes the line, so the theorems that assume it describe programs without a limit.

## Attachments to `IF`

ACL2 refuses to attach a function to `COMMON-LISP::IF`, and `spec/formats.md` excludes an `attach` line whose target is `IF`. `index-lines` in `compiler/index.lisp` refuses such a line as an invalid attachment, so the compiler writes no executable, and the runner refuses it as a line not in the format. The indexing check `data-indexable-lines-p` and the source relation `data-source-line-spelled-p` exclude the line too. `data-attachment-to-if-is-refused` shows that the check refuses a program that attaches `ACL2::F` to `IF`.

## Names that are not variables

Rules 3 and 4 of the variable rule of `spec/language.md`, section 5, exclude a name that begins with `&` and a name that both begins and ends with `*`. `variable-name-p` in `compiler/index.lisp` applies both rules, so `bind-formal` refuses such a formal, and the runner's check of a definition applies them as well. `data-ampersand-and-starred-names-are-not-variables` checks examples of each kind, a name that only ends with `*`, and `ACL2::||`, which is a variable.

## ACL2's refusals

ACL2 8.7 rejects a formal named `&` and the attachment to `IF`. The session below ran on 2026-11-26 in 0.20 seconds with 411,904 KiB peak resident memory. ACL2 described `&` as a lambda keyword and reported `find stobjs-out for IF.`

```sh
mkdir -p build/p3/continuation/tmp
TMPDIR="$PWD/build/p3/continuation/tmp" SBCL_USER_ARGS='--dynamic-space-size 2500' acl2 <<'ACL2'
(in-package "ACL2")
(defun p3-ampersand-formal (&) &)
(encapsulate
 (((p3-example-f * * *) => *))
 (local (defun p3-example-f (a b c) (if a b c))))
(defattach p3-example-f if)
(good-bye)
ACL2
```
