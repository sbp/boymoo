# The cases of the checker

Each directory here is a case: `library.txt`, `statements.txt` and `proofs.txt`, the three inputs of `spec/formats.md`, section 5 (a missing file is an empty input), and `verdict.txt`, the first line that a checker must write for them (section 9). `sh checker/test.sh` runs every case on the checker, on the runner and inside ACL2; to run one case with `sh checker/check.sh LIBRARY STATEMENTS PROOFS`, give an empty file for each input that is missing. The same layout serves every checker of `PLAN.md`, step 4.

The verdict of each case is what the specification says of its inputs, and not what some checker gives. A case whose name begins with `reject-` tests one condition, and the line that its verdict names is the first line that fails it; one that begins with `accept-` or `provisional-` is admitted in full. The proofs of the cases that are accepted use only the eight rules and the ground theory: among them the proof of `(o-p '0)` from the definitions of `o-p`, `o-finp`, `atom`, `not` and `natp`, in `accept-measure` and `accept-induct`.

The table lists each condition of the specification, the section that states it (`formats.md`, `language.md` and `logic.md` are in `spec/`), and the cases that test it.
