# Plan

This is the order of the work on Boymoo, what each step gains, and how each is judged finished. [`README.md`](README.md) says what Boymoo is for, and [`DETAILS.md`](DETAILS.md) what is in the repository and how to run it. ACL2 Core is the language that [`spec/language.md`](spec/language.md) defines.

A step is finished when its test passes by one documented command, with the date and the result recorded where the claim is made.

## The steps

| | Step | State |
|---|---|---|
| 1 | The specification | Written; under review |
| 2 | The exporter, inside ACL2 | Written; its test passes |

### 1. The specification

**What it is.** The documents of `spec/`: the language, the logic and the interchange formats, with the ground theory as data, written so that two people who never speak could each write a checker and agree on every verdict.

**What it gains.** Everything after it is written from it. Each later step can be judged against a text instead of against a program.

**Finished when** `sh checks/run.sh` passes, so that every statement about ACL2 in the specification is confirmed by ACL2 8.7; and when a reviewer who attacks the seven steps of the argument in `spec/logic.md`, section 9, finds no step that fails.

### 2. The exporter, inside ACL2

**What it is.** A program run by ACL2 that writes, in the format of `spec/formats.md`:

- for a book, its statements, with the statements of the books it includes before them, each book once;
- for ACL2 itself, its built-in library: every function in logic mode and every theorem of the world ACL2 starts with, other than the ground theory. The definitions stand in an order in which each comes after the functions its body calls, and the functions with no definition are `constrain` statements (`spec/logic.md`, section 7);
- for both, the same definitions as program text for a runner, and with them the functions in program mode for which ACL2 has a definition in its own language. ACL2's world stores no body for the program-mode functions it starts with, so the exporter translates the events that defined them; and what some of them do is given only by Common Lisp code under ACL2, for which there is no program text (`spec/language.md`, section 7);
- beside each book, what has no logical content but helps a prover: the local events, the hints, and the measures and well-founded relations ACL2 used.

It takes each statement from ACL2's world, after ACL2 has processed the book: the stored body of a definition and the ruler-extenders stored with it, the stored formula of a theorem, the stored constraint of an `encapsulate`, the stored axiom of a `defchoose`, the imports ACL2 holds for a package and whether it keeps the package hidden, a `reserve` line for every other name the world has in use, and, in the program text, an `attach` line for every attachment in force.

**What it gains.** Every book that ACL2 can load becomes input at once, with no translator to write or trust beyond ACL2's own. It also gives the first measurements: the size of the statements of real books in a format where every symbol carries its package, which decides whether the format needs an abbreviation.

**Finished when**, for ACL2's built-in library and for a chosen set of books, one command writes the statements; the reader of `checks/reader.py` reads every file; ACL2, reading each file back, confirms that every statement is the event of its world with that name; and the number of statements of each kind is recorded.

**Where it stands.** The exporter is in `export/`, and `sh export/run.sh` runs it on the library and on the books that `export/books.txt` lists. Run on 2026-11-21 with ACL2 8.7, it took 196 seconds; every file it wrote was read by `checks/reader.py`; and ACL2, reading each back, confirmed every line of every file. Its counts and sizes are in `build/export/summary.txt`.

- **The library:** 4,151 statements: 3 `package`, 1,394 `define` (of 1,452 functions), 95 `constrain` (of 163 functions), 371 `theorem` and 2,288 `reserve`. Every function in logic mode of the world ACL2 starts with, other than the 36 of the ground theory, is introduced by exactly one statement, and so is each of its 519 theorems, 371 as `theorem` statements and 148 as formulas of a `constrain` statement. Its program text has 5,879 lines: the 36 definitions of the ground theory; 1,392 of the 1,394 definitions, all but those of `hard-error` and `throw-nonexec-error`, at which a runner stops as ACL2 does (`EDGE-CASES.md`, entry 2.2); 4,382 definitions of 4,701 functions in program mode, each `mbe` replaced by its executable half; and an `attach` line for each of the 69 attachments in force. The 111 other functions in program mode have no program text: the 106 that ACL2 lists as having raw code, and 5 whose definitions call functions that ACL2 allows only under a trust tag.
- **The books:** 460 chosen, all certified; all 460 exported, read back and confirmed. 458 are distributed with ACL2; `build/outer` is a book of `checks/run.sh`, and `build/choice` is `export/choice.lisp`, which holds two cases that no certified book of the distribution keeps. Of the 13,306 files `.lisp` under ACL2's directory of books in this installation, 958 have a certificate. A book is included only with a valid certificate (`:uncertified-okp nil`), so a book without one is not exported and is counted with the cause; no book chosen was refused. The chosen books include, for each kind of statement and each awkward case, a book that has it: `choose` (13 distinct lines, two of them strengthened), `axiom` (6), `hidden-package` (3, among them a package declared hidden and then openly), `defstobj` and `defabsstobj`, mutual recursion, relations other than `o<` (`l<` in `build/choice`, `e0-ord-<` in `ordinals/e0-ordinal`), attachments, program mode, fractions and complex rationals. Their statements, each book with those of the books it includes, number 113,576: 3,251 `package`, 3 `hidden-package`, 27,980 `define`, 729 `constrain`, 29 `choose`, 50,574 `theorem`, 6 `axiom` and 31,004 `reserve`; 15,411 lines are distinct. Beside them, the prover's aids hold 3,039 local events, 7,001 hints, 2 sets of instructions and 1,191 measures, 148 declared and 1,043 chosen by ACL2.
- **Sizes:** the library's statements are 3,077,290 bytes and its program text 48,361,580; the books' statements 230,930,855 bytes in all, their program text 88,380,274 and their aids 11,730,510. Of the library's statements, package names with their `::` are 45% of the bytes; of the books', the package lines are 80%, since each book carries the packages of the books it includes, and package names are 51% of the rest. Nearly all of those names are `ACL2::` and `COMMON-LISP::`. `gzip -9` reduces the library's statements to 9% of their size, and the books' to 18%.
- **What the formats could not say as ACL2 does.** ACL2 holds the definition of a function defined inside an `encapsulate` under the function's own name, and some formulas of a constraint, the corollaries of rule classes, under none; a `constrain` statement, which may not introduce one name twice, names these formulas `F definition` and `C constraint N` (2 in the library, 18 in the books). Where ACL2 records no constraint, as for 14 `encapsulate` events of the library, the formulas are the theorems ACL2 holds about the functions. The statement `constrain` of an `encapsulate` stands after the statements of the events inside it that are not part of its constraint, which cannot mention its functions, since its formulas may mention theirs. The notes of each book mark what ACL2 records of trust tags (10 books), of certificates that record axioms (1) or skipped proofs (none) and of redefinition (none); the exporter refuses none of these.

### 3. The reference runner, in C

**What it is.** A small program in C that reads program text in the format and computes the value of a term, by the definition of value in `spec/language.md`, section 4: the seven kinds of data with integers of any size, the 32 primitive functions, and calls of defined functions. It runs an attachment in place of a function that has one, and stops at a call of a function that has neither a definition nor an attachment, as ACL2 does.

**What it gains.** The durable base: a checker written in ACL2 Core can be run with nothing but a C compiler, and later with no C compiler at all (step 7). It is not trusted for any proof; it is trusted to compute, and it is small enough to read.

**Finished when** it gives ACL2's value on the calls of `checks/expected/facts.txt` that ACL2 Core computes and on a set of programs taken from ACL2's library, compared with ACL2 by one command; and when its size in lines is recorded.

**Where it stands.** The runner is in `runner/`: 2,309 lines of C that are neither blank nor wholly comment (`sh runner/size.sh`, 2026-11-20), in ISO C99 with nothing beyond the library of C, built by a `Makefile` for the `make` of POSIX. `runner/README.md` says how to build, run and test it, what it conforms to, and what it does at each stop. It needs the packages as well as the program text, and `spec/formats.md`, section 5, now says where it takes them from, and which of two `define` lines for one function is in force.

- **The test.** `sh runner/test.sh`, run on 2026-11-20 with ACL2 8.7, printed `all runner tests passed`, both for the build of the `Makefile` and for a build with the address and undefined-behaviour sanitizers. The runner gave ACL2's value on the 153 calls of `checks/expected/facts.txt` that ACL2 computes and stopped at the 4 that it refuses; did the same on the 75 and the 1 of `checks/expected/edge.txt`; on the 18 calls of `runner/test/book.lisp`, a book of stops (11 values, 7 stops); on 2,150 calls of 86 functions of ACL2's library, run from its program text; and on 4,000 calls of the arithmetic primitives on large integers, fractions and complex rationals. It ran a recursion a million calls deep, read and wrote a datum nested a million levels deep and numbers of a million digits, stopped cleanly where memory ran out and on text that is not in the format, and read and compiled every definition of the library and of the 460 books of step 2.

### 4. The checker, and a second checker

**What it is.** The checker of `spec/logic.md`, written in ACL2 Core, so that the runner of step 3 runs it and it can later check itself. Beside it, a second checker written from the specification alone, in another language and without sight of the first.

**What it gains.** Every book gets at least a provisional verdict: with the library given and every proof skipped, the verdict says how much remains to be proved, and it already confirms that the statements are well formed, that every name is new and every symbol exists. Two checkers that agree are the test of the specification's first claim.

**Finished when** both give `accepted` on `spec/example`; both give the same first line on every input of a set of tests that has at least one rejection for each condition of the specification; and both give the same provisional verdict on every book of step 2.

**What keeps the test worth something.** A change to either checker is made from the specification, never from the other checker's code: neither checker's source is read to write or change the other. Where the two disagree, the specification is made to say what it means, each checker is changed from that text, and both are run again. Each keeps its own cases, and each is run on the other's.

**Where it stands: the checker in ACL2 Core.** It is in `checker/`: six ACL2 books in the package of `checker/package.lsp`, 1,671 lines that are neither blank nor wholly comment (`sh checker/size.sh`, 2026-11-20). ACL2 8.7 certifies them in logic mode, which proves that each of their 190 functions terminates; their guards are not yet verified, which is step 5. The exporter writes them as 182 `define` lines, one `package` line and 27 `reserve` lines. The checker takes the bytes of `spec/ground.txt` and of the three inputs as four strings and does all the reading itself, so that a line that is not in the format is a rejection and never a stop of the runner; `sh checker/check.sh LIBRARY STATEMENTS PROOFS` writes the strings with `od` and `awk`, has the runner compute the verdict from the checker's program text, and prints it. The runner is unchanged. As in ACL2, a call in the executable half of an `mbe` does not make a definition recursive (`spec/logic.md`, section 6), so the library has 502 given definitions, ACL2's own `string-append` not among them.

- **The test.** `sh checker/test.sh`, run on 2026-11-20, printed `all checker tests passed`. On the runner, `spec/example` gave `accepted`; each of the 319 cases of `checker/cases/` gave its verdict, among them at least one rejection for each of the 74 conditions that `checker/cases/README.md` lists with the section that states it; every function called in the checker's `define` lines is a primitive, a function of the ground theory or one of its own (`checker/closed.py`); and the checker's own statements, with an empty library and a skip for each of their 87 obligations, gave `provisional skipped 87 assumed 0 given-definitions 0 given-facts 0`. ACL2, computing the same functions on the same bytes, gave the same verdict on all 321 inputs.
- **Time.** Measured on 2026-11-20 with `-v`: on the runner, admitting the library, 4,151 statements and 3 MB, takes 1.45 seconds of processor time and a peak of 159 MB; with the largest book, `std/strings/pretty`, 3,918 statements and 2.3 MB, and its 2,500 skips, the run takes 3.07 seconds and a peak of 180 MB. - **The books.** `sh checker/books.sh`, run on 2026-11-20, ran the checker on the runner on all 460 books of step 2, with `build/export/library.statements` as the library and a skip for each obligation, which `checker/skips.py` writes into `build/checker/skips/`; it took 995 seconds, of which the runner's part is about two seconds a book and the rest the shell and the skips, and wrote the verdicts to `build/checker/books.txt`. ACL2 gave the same verdict on every book (`sh checker/acl2-check.sh < build/checker/books-list.txt`, 418 seconds).

### 4b. The exporter, proved

**What it is.** Proofs in ACL2 that the exporter of step 2 writes what it should. The exporter is split for them into a **core**, ACL2 books of functions in logic mode with no state, from ACL2's world to the lines written as data, and a **shell**, which takes the world from the session, prints each line with the printer of `checks/canon.lisp` and writes the files. The proofs are about the core and the printer, and say:

1. **The round trip.** The reader of `checker/read.lisp`, applied to the text that the printer writes for a datum, gives the datum back.
2. **No crash.** The guards of the core and of the printer are verified.
3. **Faithfulness.** Each statement written says what the world holds for its name: the stored body and ruler-extenders of a definition, the stored formula of a theorem, the stored constraint, the stored axiom of choice, the imports a package declares.
4. **Completeness without repeats.** Each name that the world introduces in the range exported gets exactly one statement.
5. **Order.** Each statement comes after the statements that introduce what it uses.
6. **Well-formedness.** Every line written is a statement of the format.

**What it gains.** Trust in the statements rests on theorems about the code that writes them, and not only on reading that code and on the read-back check, which compares the output with the world for the books tried and no others.

**What it does not cover.** That ACL2's world means what the core takes it to mean: that a property such as `unnormalized-body` or `constraint-lst-etc` holds what ACL2's documentation and source say. What the shell computes: the translations of the bodies of the functions in program mode that ACL2 starts with, which ACL2's `translate-cmp` makes, and the local events read from the books' sources for the prover's aids. The bytes that reach the disk. The one function in raw Lisp of the read-back check, and the shell scripts and the Python that drive the exporter.

**Finished when** ACL2 certifies the books of the core and of the proofs with no skipped proof, no trust tag and no added axiom; `sh export/run.sh` writes, byte for byte, what it wrote before the split; and each theorem is listed with what it says in plain words.

**Where it stands.** Finished, by the measure above. The six properties are proved, about the lines that the core returns and about the printer and the reader of their text, and the guards of the core and of the printer are verified. ACL2 certifies the books of the core and of the proofs with no skipped proof, no trust tag and no added axiom; `sh export/run.sh` writes the same bytes as before the split ("The same output", below); and each theorem is listed below with what it says. The proofs are 56 ACL2 books in `export/proofs/`, 17,625 lines and 809,811 bytes (`wc -l -c export/proofs/*.lisp`), in five sets. Each set has a script, which certifies its books, refuses a certificate that records a skipped proof, an added axiom or a trust tag, and tests on ACL2's own worlds that the hypotheses of its theorems hold; and a report, `export/proofs/NAME.md`, which gives every theorem with its hypotheses and their tests. The script of `guards` checks the certificates of the printer and of the core in the same way. One command runs them all, from the root of the repository: `sh export/prove.sh`. Run on 2026-11-21 with ACL2 8.7, it printed `all proofs passed`, in 700 seconds: `round-trip`, 9 books and 2,710 lines, in 8 seconds; `guards`, 7 books and 2,166 lines, in 191; `structure`, 15 books and 4,597 lines, in 42; `well-formed`, 6 books and 2,151 lines, in 117; and `faithful`, 19 books and 6,001 lines, in 341. On the same day `sh checks/run.sh` printed `all checks passed`.

The theorems are about the entries of the core (`export/README.md`): `bx-library-lines`, which gives the lines of the library, and `bx-book-lines`, which gives those of a book; those of the guards are also about `bx-translation-requests`, which gives the bodies that the shell is to translate. A statement is one of the statements that either returns. A property is "stored" when ACL2 holds it in its world, as its function `getprop` reads it, which gives `NIL` for a property that is absent. Each hypothesis about the world is tested on the worlds named.

- **1. The round trip** (`round-trip`). The reader is `parse-line` of `checker/read.lisp`, which the script certifies from the checker's own books.
  - `rt-parse-printed-line`: given the text that `bm-line` writes for a line, followed by a line feed, the reader gives back the line's word and the reader's form of its data. Hypotheses: the word is a word of the format that the reader's table of words admits; the data are a proper list of ACL2's data, that is numbers, characters, strings, symbols whose package name is not empty, and conses of these; and every symbol written is of a package that the reader's table of packages declares, whose declared imports hold no symbol of its name, the table's index of imports being built from those declarations. Tested with tables made from the packages that ACL2 holds at startup and after including `arithmetic/rationals`, `std/osets/top` and `std/strings/pretty`, on data of every kind, nested and dotted lists among them.
  - `rt-datum-form-injective`: two data have the same form in the reader exactly when they are the same data. In that form, the symbol written `P::N` is the symbol of the package `BOYMOO` whose name is `P::N`, and `COMMON-LISP::NIL` and `COMMON-LISP::T` are `NIL` and `T`. So the reader's form of a line determines the data written.
  - `rt-package-index-agrees-with-declarations`: with the index built so, the reader's test of a symbol is the rule of existence of `spec/language.md`, section 2.
  - `rt-accepted-line-has-reader-text`, with no hypothesis: each line that the reader accepts is, character for character, the text of the word and the data it returns. `rt-accepted-line-with-compatible-packages-is-printer-text`: if no word of the table is empty, and each package of the table excludes every name that ACL2 imports into its package of the same name, each line that the reader accepts is the text that `bm-line` writes for some data of ACL2, followed by a line feed. Tested on the same tables.
  - What it does not say. A table that declares a package with fewer imports than ACL2's package of the same name lets the reader accept a symbol that ACL2 cannot hold, such as `BOYMOO::CAR`, whose text no data of ACL2 has (`rt-conflicting-native-import-has-no-preimage`). Objects that are not data of ACL2's logic are outside, and so are the bytes on disk. The theorems are about ACL2's logic; with guard checking off, ACL2's evaluator at its top level refuses to give the package name of a symbol of a hidden package (`export/proofs/round-trip.md`).
- **2. No crash** (`guards`). A guard is a condition on the arguments of a function, declared with it. ACL2 verifies a function's guard by proving that, on any arguments that meet it, each call that the function makes meets the guard of the function called. On such arguments ACL2 may then run the function as compiled Common Lisp, with no check at each call, and the result is the value of its definition in the logic, which is what the other theorems are about. ACL2 verifies the guards of all 189 functions of the core and of the twelve of the printer, `checks/canon.lisp`: `guards.sh` confirms that ACL2 holds every function of the core, and `bm-line`, by which the shell prints, as guard-verified, and `round-trip.sh` confirms it for the printer. The guards of the three entries are conditions on the world and on what the shell hands the core:
  - `bx-translation-requests`, verified by `(verify-guards bx-translation-requests)`: the two limits of the range are integers; the world is a list of property triples (ACL2's `plist-worldp`); and every record of an event in it has the fields that the core reads, with names of the type its kind gives, a list of symbols for a definition, theorem, axiom, choice, `encapsulate`, macro, constant, label, theory or single-threaded object and a string first for a package, and, for a definition, an event form whose definitions the core can take apart (`bx-event-world-p`).
  - `bx-library-lines`, verified by `(verify-guards bx-library-lines)`: the limit is an integer; the ground functions are a list of symbols, each with stored `formals`, and so is each of ACL2's primitives; the translations are a list of pairs in which each that reports success holds a translated term (`bx-translations-p`); and the world meets `bx-export-world-p`. That is the condition on records of events above, and: every value stored in the world, current or not, of each property that the core reads is of the type it is read as: `formals` a list of symbols, and none for `QUOTE`; `unnormalized-body`, `defchoose-axiom` and `theorem` translated terms, and the imports in the axiom of each package a list of symbols; `constraint-lst-etc` a list; `justification` absent or a record with the fields read; `siblings` a list of symbols; `absolute-event-number` a rational number; `attachment` an atom, a list of pairs or the mark that refuses attachments. The table of known packages has ACL2's shape. Every function that a definition or an `encapsulate` introduces has stored `formals`. The constraint of each `encapsulate` with a signature is recorded under a name whose stored constraint is a list of translated terms or ACL2's mark of an unknown constraint, and whose siblings have stored `formals`. And each function introduced by choice is constrained, or has stored `formals` and an axiom whose second list of arguments, where the axiom is the longer one of `:strengthen t`, is empty or as long as its formals.
  - `bx-book-lines`, verified by `(verify-guards bx-book-lines)`: the guard of `bx-library-lines`, with three integer limits and two strings for the directories; and also that each definition in logic mode has declarations of the shape from which the prover's aids are read (`bx-world-aids-p`), that ACL2's records of trust tags and of included books have the shapes that the notes read, and that its record of redefinition is present (`bx-book-globals-p`).
  - These conditions are about the whole world given, the events outside the range exported among them, and leave properties that the core does not read free. Tested: `guards.sh` evaluates the three guards on six worlds, ACL2's at startup and after including, one after another, `misc/hidden-defpkg-checks/top`, `misc/defpun`, `std/alists/alist-equiv`, `std/stobjs/absstobjs` and `misc/dft-ex`, with the ground functions of `spec/ground.txt`, the translations that the shell makes and the directories that ACL2 gives, and each guard holds on all six. Beyond that, `export/book.sh` exports with guard checking on, and the shell calls the core through `ec-call`, so ACL2 evaluates the guard of each entry on each world exported, and a world that failed one would end its export with an error before any file is written: on 2026-11-21 `sh export/run.sh` exported the library and all 460 books ("The same output", below).
  - What it does not say: that the guards hold on every world that ACL2 can make, since they are conditions, tested on the worlds named, and not theorems about ACL2; that the core finishes within the time and memory at hand, although ACL2's admission of each function proves that it ends; anything of the values beyond their being those of the definitions, which the other theorems cover; anything of the shell, which is in program mode, of its translations and its reading of sources, or of the bytes written.
- **3. Faithfulness** (`faithful`). Each theorem is about a statement with the word named. Several have as a hypothesis that ACL2's world has the shape of a list of property triples in which every stored `formals` is a list; below, that is "the shape of the world".
  - `faithful-define-statement`: a `define` statement gives, for each of its functions, the stored `formals` and `unnormalized-body`, and, for all of them, the ruler-extenders of the first function's stored `justification`, or `NIL` where it has none. `faithful-define-ruler-extender-exception`: those are a function's own exactly when its stored ruler-extenders are the first function's. Hypothesis of both: the shape of the world.
  - `faithful-theorem-statement` and `faithful-axiom-statement`, with no hypothesis: the formula is the stored `theorem` of its name. `faithful-fact-statement-has-world-record`: that formula is present, if every theorem, axiom and choice that an event of the world names has its formula stored; that is its one hypothesis.
  - `faithful-package-statement`: a `package` statement gives the imports that ACL2 records for an open package, which are those of its axiom; its one hypothesis is that the table of known packages is present and agrees with those axioms. `faithful-hidden-package-statement`: a `hidden-package` statement gives the imports recorded for a package that ACL2 holds hidden or once declared hidden; its one hypothesis is that the table is present.
  - `faithful-choose-statement`: a `choose` statement gives its function's stored formals, and the axiom that `spec/logic.md`, section 6, builds from it is the stored `defchoose-axiom` once every lambda application in each is replaced by its body; or, for a function with no formals, the stored axiom is the longer one of `:strengthen t`, which adds only that the call of the function equals itself. Hypothesis: the shape of the world.
  - `faithful-constrain-statement`: a `constrain` statement lists exactly the functions that ACL2 records as sharing the constraint, each with its number of formals; names every formula; and, where ACL2 records the constraint, the conjuncts of its formulas are all and only the recorded ones, in any order and number. `faithful-constrain-formula-source`: each formula is the stored theorem of its own name, or, under a name that the core makes, a sibling's stored axiom of choice, a sibling's defining equation, or the recorded conjunct at the position the name gives. `faithful-generated-name-introductions-stay-with-owner`: any statement that introduces the same made name is a `constrain` statement with the same formula and the same constraint. Hypotheses: the shape of the world; every encapsulate's signature functions are among its recorded siblings, which have formals and one owner of the constraint, and a recorded constraint is a list of conjuncts; for the second theorem, also that every theorem, axiom and choice has its formula stored; for the third, also that every function that an event defines or introduces by choice has its formals stored.
  - `faithful-book-constraint-statement-or-note` and `faithful-library-constraint-statement-or-note`: with the hypotheses of `faithful-constrain-statement`, each `encapsulate` with a signature in the range gives such a `constrain` statement, or the note that no unused name was found for a formula, which names every function and every named formula of the constraint (`faithful-book-exhausted-constraint-names-noted`, `faithful-library-exhausted-constraint-names-noted`). The library's may instead give the note that its order was not completed, which `structure-walk-library-fuel-suffices` shows it never gives.
  - `faithful-reserve-statement`, with no hypothesis: ACL2 holds the name as a macro, a constant, a label, a theory, a single-threaded object or the variable of one.
  - For the program text, `faithful-library-program-define` and `faithful-book-program-define`: each definition gives the stored formals, and the stored body or, where none is stored, the translation that the shell supplied, with each `mbe` replaced by its executable half. Hypotheses: the shape of the world; each function in program mode of a single-threaded object has its body stored, and, for the library, no function of the ground theory is in program mode. `faithful-attach-program-line`, with no hypothesis: each `attach` line gives a pair that ACL2's `attachment` property records.
  - Tested: every hypothesis on seven worlds, ACL2's at startup, after including each of `misc/hidden-defpkg-checks/top`, `misc/defpun`, `std/alists/alist-equiv`, `std/stobjs/absstobjs` and `misc/dft-ex`, and after `misc/defattach-example` with examples of packages, choices, guard holders and program mode; the predicates of the theorems, computed apart from the core, agree with the 4,151 statements and 1,499 program lines of the library and with the 394 statements and 158 program lines of those books.
  - What it does not say: that a property means what ACL2's documentation says it does; which attachments are new beside those of the world ACL2 starts with; the ruler-extenders of program text; the translations that the shell makes; the notes, beyond what is said of them here, and the prover's aids.
- **4. Completeness without repeats** (`structure`).
  - `structure-library-lines-complete-or-note` and `structure-book-lines-complete-or-note`: each name that an event in the range introduces, and that is due a statement, is introduced by exactly one statement, or a note names it, or both; for a book the count runs over the library and the book together, and a line repeated byte for byte counts once. A name is not due a statement if it is a function defined in program mode, which has program text; the file of an `include-book`; or a name of an event of another kind with no function in logic mode, no theorem and no reserved-name property. Nor, in the library, is what the ground theory holds: its five packages, `T` and `NIL`, the functions it defines, and ACL2's 84 axioms. Hypotheses: the numbers of the events in the world are integers that decrease, and the depths of those in the range are integers; the name is one of an event in the range, whose record has the shape that its kind gives; and, for a book, the library is the one that the core computes again from the world. Tested on ACL2's world at startup and after including `std/lists/append`, `misc/defpun`, `std/stobjs/absstobjs`, `misc/hidden-defpkg-checks/top` and `ordinals/e0-ordinal`, each alone and the five together: every name of every event in the range, found by a walk of the world written apart from the core, has its statement or its note, and the library computed again is the library exported.
  - `structure-library-lines-report-second-introduction`, with no hypothesis, and `structure-book-lines-report-second-introduction`, whose one hypothesis is that the library is the one the core computes again: if two different statements introduce one name, a note names it as in use.
  - `structure-fresh-name-excludes-registered-symbols`, with no hypothesis: a name that the core makes for a formula is a symbol of its function's package, not a keyword, and no function, theorem or reserved name of the world. `structure-book-lines-generated-name-bound`, with `structure-library-lines-generated-name-bound` and `structure-book-output-generated-name-bound` for each file alone: a symbol that is no such name of the world is introduced by at most as many statements as there are events that could make it. Hypotheses: those of completeness, and that the records of the ranges have the shapes from which names are made. Tested on every made name in the outputs above: one event could make each.
  - `structure-walk-library-fuel-suffices` and `structure-library-order-keeps-line`, with no hypothesis: the walk that orders the library never runs out of steps, and keeps every statement.
  - What it does not say: that a statement says what the world holds or is of the format, which the other theorems cover; or that a name with a note has no statement too.
- **5. Order** (`structure`).
  - `structure-library-lines-order-or-note` and `structure-book-lines-order-or-note`: the statements, for a book after those of the library, are in order, or the notes hold a note of order, for a book one about the library or the book. "In order" is defined in `export/proofs/structure-spec.lisp`, apart from the core: every function that a term calls, in the bodies of lambdas and in both halves of an `mbe`, is in use, with that number of arguments; a `define` or a `constrain` has its own functions in scope, and a `choose` only those before it; every symbol is of a package declared before, and is not of a name that the package imports; every name introduced is new and appears once on its line; and an open package may follow a hidden one with the same imports. Hypotheses: the declarations to start from are the ground theory's, as the core reads them from the world and the list of ground functions; and, for a book, the library is the one that the core computes again. Tested: the script reads the ground theory's declarations from `spec/ground.txt` and compares them with the world's, and checks the library and each of the five books above with the definition of order.
  - `structure-library-notes-count-order-failures` and `structure-book-notes-count-order-failures`: there are at least as many notes of order as lines that fail the definition.
  - What it does not say: the rules of names beyond being new, that a function name is not `QUOTE` and, in a book, not a symbol of `COMMON-LISP`; the proofs that the statements call for; and that a checker reaches the lines after one it cannot admit: it stops there, while the core's check goes on to report the lines after it.
- **6. Well-formedness** (`well-formed`).
  - `well-formed-library-statements` and `well-formed-book-statements`, with `well-formed-library-statement-with-names` and `well-formed-book-statement-with-names` for each statement alone: the statements are a list of lines of `spec/formats.md`, section 4, each word with its number and shape of fields; every term a translated term, made of legal variables, quotes of data, calls with terms as arguments and lambdas whose bodies use only their formals; every name a symbol that is not a keyword, and no function named `QUOTE`; the formals of each definition distinct; and every formula of a constraint named. Hypotheses: the bodies, theorems and axioms of choice that ACL2 stores are terms with legal variables, lambdas and quoted data; stored formals are distinct legal variables; the table of known packages has ACL2's shape; and the properties read for the events of the range are present. Tested on ACL2's world at startup and after including `std/lists/append`, `misc/defattach-example`, `std/system/defchoose-queries`, `std/stobjs/1d-arr`, `misc/hidden-defpkg-checks/top`, `misc/defpun` and `std/strings/pretty`, and the recognizers accept every line that the core writes there.
  - `well-formed-library-program` and `well-formed-book-program`: the program text is a list of lines of the format, if, besides, the world is a list of property triples, the targets of its attachments are symbols, every translation that the shell supplied is a term, and, for the library, the functions of the ground theory have stored bodies.
  - `well-formed-fresh-constraint-name`, with no hypothesis: a made name is `NIL` or a symbol of its function's package, not a keyword and not in use. `well-formed-equal-made-names-have-same-source`: two names made for formulas, each from a function and a kind of name with its position, are the same only if they were made from the same function, kind and position.
  - What it does not say: whether the symbols exist and the names are new, which the order covers; which functions are in use; the conditions that `spec/logic.md` puts on each statement; the notes and the prover's aids.
- **What stands outside the theorems.** Two cases are known in which the lines differ from what ACL2 holds, and the notes report each:
  - The ruler-extenders of a group of mutually recursive functions that declare different ones (see "Undecided"): the `define` statement gives the first function's.
  - Two nested encapsulates with signatures whose constraint ACL2 records once, under the outer function: the core writes that one constraint twice, as a `constrain` statement at each encapsulate, both with the same functions and the same made name for the same conjunct, so that a checker refuses the second; the core's check of order reports those names as in use. `export/proofs/structure.md`, `well-formed.md` and `faithful.md` give the example, which their scripts run. One statement, at the outer encapsulate, would say what ACL2 holds.

  Beyond the theorems lie the shell, the prover's aids, the notes beyond what is said of them above, what ACL2 means by its properties, and the bytes on disk.

**The core and its output.**

- **The books.** `export/core.lisp`, 2,567 lines and 115,008 bytes, holds the core: 189 functions, every one in logic mode with a declared guard, admitted by ACL2 with no hint and no lemma, five of them with a declared measure. 49 of them are the predicates by which the guards say what shape the world's records must have. The book of the core declares the guards and does not verify them; the seven books of `guards`, which include it, verify them. Four functions whose recursion ends for a reason not plain from their arguments count their steps with an argument whose bound is never reached. It includes one book of ACL2's distribution, `system/remove-guard-holders-weak`, which puts one function of ACL2 in logic mode. `checks/canon.lisp`, 233 lines and 10,144 bytes, is the printer: 12 functions in logic mode, whose guards ACL2 verifies; every script that prints loads it, through `checks/canon.lsp`, and the exporter includes it as a certified book. `sh export/certify.sh` has ACL2 8.7 certify both into `build/export/acl2/`, the core in 1.4 seconds; `sh export/certify.sh --guards` certifies the books of `guards` after them, and `--fresh-guards` certifies those again from the start.
- **The shell.** `export/export.lsp`, 205 lines, 13 functions in program mode: it takes the world from the session, translates the bodies of the functions in program mode that ACL2 starts with, which the core asks for, with ACL2's `translate-cmp`, reads the local events of the books from their sources, and prints and writes each line. `export/book.sh` has `export/certify.sh --guards` certify the books, includes the book `guards`, which includes the core with its guards verified, and runs the export with guard checking on. The shell calls each function of the core through `ec-call`, so that ACL2 checks the guard on the arguments given before it runs the core's compiled code; a guard that does not hold ends the export with an error.
- **ACL2's functions in program mode.** The core calls none. For the seven functions by which ACL2 reads its record of an event, for `signature-fns` and for `lookup-world-index` it has definitions of its own; for `remove-guard-holders` it uses `remove-guard-holders-weak`, which leaves out a simplification of quoted lambda objects, with the same output on every file exported; `translate-cmp` and the reading of sources are in the shell.
- **The same output.** On 2026-11-21, `sh export/run.sh` under ACL2 8.7 wrote the same bytes as before the split in each of the 1,843 files of the library and of the 460 books, their statements, program text, aids and notes, by their SHA-256 checksums. It took 196 seconds, by its own clock in `build/export/summary.txt`, against 263 before the split: the core finds a repeated line by its data, where the exporter printed every statement of the library again for each book. On the same day `sh checks/run.sh` printed `all checks passed`, `sh runner/test.sh` printed `all runner tests passed`, and `sh checker/test.sh` printed `all checker tests passed`.

### 5. Review

**What it is.** First, testing against ACL2: for every proof that the checkers accept, a book that states the conclusion of each step as a theorem, which ACL2 must certify; and for every definition, a comparison of the obligations of termination with ACL2's own measure conjectures. Then the system on its own source: the proofs of termination of the checker's own functions, checked by the checker, and of the guards of its functions. Guards are no part of the logic; here they are theorems which show that the checker's code never calls a primitive outside the arguments it is meant for, so that it may be compiled without checks.

**What it gains.** Confidence from two directions: ACL2 agrees with every step the checker took, and the checker's own source is among the things it has checked.

**Finished when** ACL2 certifies the book of steps for every accepted proof, and the checker gives `accepted`, with an empty library, on its own source.

### 6. The prover

**What it is.** A program that finds proofs in the eight rules. It works upward from the built-in library: first the termination of ACL2's own definitions and the theorems ACL2 holds about them, then the books. It may use anything to find a proof, the hints and local events of step 2 among them, since the checker judges the result. For termination it gives each definition a measure built from the functions in use at that definition. ACL2's own measure is a starting point and not always usable as it stands: it may call a function that comes later, be stated with another well-founded relation, or not be stored at all (`spec/logic.md`, sections 6 and 7).

**What it gains.** What was given or skipped becomes proved. Each count of a provisional verdict falls, and a book reaches `accepted` when its counts and those of everything it rests on reach 0.

**Finished**, for a set of books, when the verdict on each is `accepted`: nothing skipped, nothing assumed and nothing given, the library's own statements being proved too. How the library's proofs reach a checker is not settled (see "Undecided").

### 7. The compiler

**What it is.** A compiler from ACL2 Core to machine code, written in ACL2 Core. The reference runner runs it once to compile itself.

**What it gains.** Speed, and a stack with no C compiler under it: the checker, compiled by a compiler that the checker's own logic can reason about.

**Finished when** the compiled compiler, compiling its own source, gives its own bytes again; and the compiled checker gives the verdict of the runner's checker on every input of step 4, in a recorded fraction of the time.

### 8. Larger proof steps

**What it is.** Rules that do in one step what takes many in the kernel: the opening of a definition, rewriting with a lemma, evaluation of a defined function on constants with a budget of steps, the use of a theorem about constrained functions at other functions that meet the constraints, and arithmetic. Each is a function from its premises to a conclusion, admitted only with a proof, at the level below, that its conclusion always follows.

**What it gains.** Shorter proofs and faster checking, with the trusted rules still the eight.

**Finished**, for each rule, when its proof of soundness is accepted by the checker and the size of the proofs of step 6 with and without it is recorded.

## Undecided

These matters are not settled, and the specification says so where they arise.

- **Recursion inside the quoted lambda of a `loop$`,** which ACL2 measures and ACL2 Core does not yet (`EDGE-CASES.md`, entry 6.14).
- **A `choose` entry in the proofs.** `defun-sk` makes a `constrain` statement whose formulas, in general, only a choice function meets, and a proof may define functions but not introduce one by choice, so such a statement can only be skipped (`EDGE-CASES.md`, entry 6.9). A `choose` entry, admitted as a `choose` statement is, would let a proof hold the local `defchoose` that ACL2 used. It would add a word to `spec/formats.md`.
- **The values of the character functions with unknown constraints.** ACL2 proves by running the Common Lisp under it what `char-upcase`, `char-downcase`, `upper-case-p`, `lower-case-p` and `alpha-char-p` give on the 160 characters that are not standard, and decides by the same code whether a package name has a lower-case character (`EDGE-CASES.md`, entries 1.4 and 7.2). The library could hold these 800 values as theorems; they depend on the host. The double-floats of entry 1.5 have no such finite table.
- **What program text says beyond definitions.** A runner differs from ACL2 where ACL2 runs the executable half of an `mbe` because a function's guards are verified, and where ACL2 refuses a constant in place of a single-threaded object (`EDGE-CASES.md`, entries 2.5, 2.7 and 3.4). Program text that marked guard-verified definitions and single-threaded arguments would let a runner stop where ACL2 does.
- **Names that ACL2 refuses for reasons outside the logic.** ACL2 refuses a function named by a symbol that the Lisp under it defines, a package named as one of that Lisp's packages, and any event that calls a function it holds untouchable; ACL2 Core refuses none of these (`EDGE-CASES.md`, entries 6.1 and 7.2). The library could reserve the names of one host and mark the untouchable functions.
- **A package of the ground theory declared again.** ACL2 accepts `(defpkg "KEYWORD" nil)` and `(defpkg "COMMON-LISP" nil)` as redundant. ACL2 Core refuses the `package` statement `(package "KEYWORD" COMMON-LISP::NIL)`, although it is, byte for byte, a line of the ground theory, because the ground theory is no input and a package may not be declared twice (`spec/logic.md`, section 6; `EDGE-CASES.md`, entry 7.1). The case `checker/cases/reject-repeat-ground-package` shows it. No statement that ACL2 writes is affected.
- **A world that a trust tag, redefinition, skipped proofs or a book with no certificate has changed.** ACL2 records each of these in its world (`EDGE-CASES.md`, entries 8.2 to 8.5). Every statement still needs its proof, but a world changed under a trust tag may hold what the book's text does not say. Whether the exporter refuses such a world, or marks what it writes from it, is not settled.
- **How the library's own definitions are proved.** A book may not define a function whose name is a symbol of `COMMON-LISP`, as in ACL2, and ACL2's library defines 94 of them. So the library cannot simply be moved to the second input of a checker to be proved. One way is a fourth input that holds proofs for the library.
- **Whether a symbol may be abbreviated.** Every symbol is written with its package (`spec/formats.md`, section 4). Step 2 measured what that costs: about half the bytes of every statement other than a package line, nearly all of it `ACL2::` and `COMMON-LISP::`; while the package lines are 80% of the bytes of the books' statements, and `gzip -9` leaves 9% to 18% of the size, with the format unchanged.
- **How a rejection names what failed.** The verdict gives the input and the number of the line (`spec/formats.md`, section 9), not a symbol.
- **Code of the runner's own for functions of the library.** ACL2 computes `floor`, `mod`, `nonnegative-integer-quotient` and some 280 other functions of its library with code of the Lisp under it (`EDGE-CASES.md`, entry 3.3). The runner runs their definitions, by which `(nonnegative-integer-quotient i j)` subtracts `j` from `i` once for each unit of the quotient, so that `floor` of a large number by a small one does not finish (`runner/README.md`). The runner could hold code of its own for a few such functions; it would then be trusted to compute what their definitions compute.
- **Different ruler-extenders within one group of mutually recursive functions.** ACL2 admits a `mutual-recursion` whose functions declare different ruler-extenders, and stores each function's own: for example `(mutual-recursion (defun ev (x) (declare (xargs :ruler-extenders :all)) (if (zp x) t (od (1- x)))) (defun od (x) (declare (xargs :ruler-extenders (cons))) (if (zp x) nil (ev (1- x)))))`, in which `ev` has `:all` and `od` has `(cons)`. A `define` statement holds one value of the ruler-extenders for all its functions (`spec/formats.md`, section 4), so for such a group the exporter writes the first function's and the note `clique whose functions differ in ruler-extenders`. A value for each function would hold what ACL2 stores; whether the walk of `spec/logic.md`, section 6, would then measure each function's calls under its own is not settled. On 2026-11-20, `sh export/run.sh` wrote that note for no book of `export/books.txt`.
